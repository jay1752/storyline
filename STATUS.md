# Storyline — Build Status

Reference doc for where this stands. Updated as of 2026-09-19. See also the product
design artifact ("Storyline") and mockups ("Analyst Desk", "Position Desk") from the
planning phase — this file covers what's actually *built*, not the product vision.

## Architecture, locked in

| Area | Decision |
|---|---|
| Backend | Python, FastAPI |
| UI | Jinja2 + HTMX, no JS framework — shared `Jinja2Templates` instance in `app/templates_config.py`, cache-busted static assets (`asset_version()`) |
| DB | SQLite, **two files**: `market.db` (Analytics layer, shared) + `users.db` (Management/Portfolio, per-user) — `users.db` ATTACHes `market.db` for cross-file joins |
| DB journal mode | **WAL deliberately OFF.** It crashes with a real "disk I/O error" under Docker Desktop's bind-mounted volume on macOS when multiple connections write concurrently — reproduced and confirmed this session. Default rollback journal instead. |
| Infra | Docker, single container, `docker-compose.yml`, port 8000 |
| Ingestion orchestration | A bounded **thread pool** (`app/ingestion/runner.py`, `MAX_CONCURRENT_JOBS=5`) — up to 5 sources run genuinely concurrently. Started as a single serial worker (avoided a real SQLite lock-contention deadlock); once the *actual* root cause was found and fixed (a `progress()` callback opening a second connection mid-transaction — not concurrency itself), parallelized properly. Safe because every source hits a different external API with its own independent rate limit, and each job holds exactly one DB connection for its lifetime — SQLite's own lock serializes commits via busy-timeout, never a true deadlock. Verified directly: multiple real sources (BSE, SEC EDGAR, World Bank) running concurrently in an isolated test before this shipped. |
| MCP | Parked. Business logic kept in plain functions (ingestion sources, `analytics.py` helpers), not embedded in routes — mounting MCP later should be additive, not a rewrite. |

## Analytics — the 5-layer lens, current state (US)

| Layer | Status | Notes |
|---|---|---|
| 1 · Company | **Real** | revenue, margin, EPS, YoY growth, balance sheet (debt/cash), ROE/ROCE/D-E — all from SEC EDGAR |
| 2 · Relative (sector) | **Real** | computed at read time (`_compute_sector_benchmark` in `analytics.py`), needs 3+ real peers in the same sector+quarter bucket or it's left blank — no fake benchmarks from 1-2 companies |
| 3 · Institutional | **Real** | `app/ingestion/sec13f_source.py` — SEC's bulk Form 13F data set (~100MB/quarter, ~3.8M holding rows across ~9,500 managers), aggregated up to one row per symbol: holder count, total shares held, QoQ change. Top ~3,000 CUSIPs by aggregate value mapped to tickers via OpenFIGI's free API (not the full long tail — see below) |
| 4 · Market/sector momentum | **Real, price-based** | `_compute_sector_benchmark` in `analytics.py` — for each quarter, every sector peer's trailing ~3-month price return (Tiingo for US, 5paisa for India), averaged and classified favor/neutral/out. No longer the earnings-growth approximation — genuinely price-derived now, the original Layer 4 concept. Sanity-checked against real market history (NVDA's semiconductor peers show "out" in the 2008 financial crisis, "favor" in the 2009 recovery). |
| 5 · Macro | **Real** | `app/ingestion/fred_source.py` — St. Louis Fed's free API, real quarterly history (Fed funds rate, CPI YoY, GDP growth, unemployment) going back 5 years. Verified against known Fed history (2022 inflation spike, rate hikes to 5.33%, recent cuts to 3.63%) before trusting it. India gets `worldbank_source.py` too — see India section below |
| P/E (ratios card) | **Real** | computed at read time, combining EPS (SEC EDGAR) + price (Tiingo) — neither source alone has both |
| Guidance vs. delivered | **Real** | beat/met/miss from Finnhub's free-tier EPS Surprises endpoint (`app/ingestion/finnhub_source.py`), UPDATEs `guidance_vs_delivered` on existing SEC EDGAR rows matched by nearest `period_end_date` (±15 days). Free tier only covers the last 4 quarters per symbol — older quarters stay blank, same honest-partial-coverage pattern as sector benchmarking. |

**India: real now, via BSE-direct (`bse` source).** Revenue, operating profit, margin, net profit, EPS, YoY growth for all 4 quarters; ROE/ROCE/D-E + debt/cash computed at the latest period from the annual filing's balance sheet (same convention as `sec_edgar`). Sector/Layer 2/3/4/5 and guidance-vs-delivered are still empty for India — no source for those yet. See India section below for how this source works and its known gaps.

## Real bugs found and fixed this session (not just features)

1. **WAL + Docker bind-mount crash** — `sqlite3.OperationalError: disk I/O error` under concurrent connections. Fixed: WAL off, default journal mode.
2. **Division by zero** in revenue-growth calc — a company with $0 revenue in the year-ago comparable quarter crashed the *entire* multi-thousand-symbol ingestion run (not caught per-symbol). Fixed: correct denominator guard + wrapped per-symbol processing in its own try/except (`_process_symbol`) so one bad company can never take the whole run down again.
3. **Deadlock** — the `progress()` callback opened a *second* DB connection to report progress, while the ingesting connection could still hold an open transaction. Two connections fighting for SQLite's one write lock. Looked like a hang; actually a silent 30s timeout into "database is locked". Fixed: `progress()` reuses the same connection.
4. **Fiscal Q4 gap** — 10-Q filings only cover 3 of 4 quarters (Q4 is in the 10-K). This silently corrupted the TTM window used for ROE/ROCE (spliced non-consecutive quarters across the gap). Fixed: Q4 derived as annual − sum(3 known quarters), clearly labeled `(derived)`.
5. **Balance sheet 10-K exclusion** — the instant-facts extractor only looked at 10-Q, missing the one point-in-time balance sheet snapshot that's only ever in the 10-K. Fixed.
6. **BSE XBRL scale inconsistency** — filings use a `scale` XBRL attribute that varies *between filings* (crores, scale=7, vs. lakhs, scale=5) despite every filing displaying "(in Cr.)" on BSE's own website. Caught by spot-checking a mid-cap's revenue against its market cap — a number 100x too large. Fixed: every numeric fact is normalized by its own tag's `scale` attribute, not assumed.
7. **BSE period-end date tag missing on older filings** — `DateOfEndOfReportingPeriod` (used to key `period_end_date`) is present in newer filings but absent in older ones for the same company, same symptom class as SEC EDGAR's tag-variant inconsistency. Fixed: period end date is derived from BSE's own filing metadata (`Quarter_Name` + `Yr`), which is always present, instead of an in-document tag that isn't.
8. **5paisa wrong backend** — `fivepaisa_source.py` was built against INDstocks' consumer API; a hand-rolled version of 5paisa's own official TOTP-login + access-token calls failed with `"Invalid Input Parameters"` for reasons that stayed unclear even after reading the SDK source directly — the official `py5paisa` SDK succeeded with the same credentials, so the module now uses it instead of re-deriving the exact payload shape that made the difference.
9. **Banks silently zero'd out** — banks (HDFC Bank etc.) returned 0 quarterly rows because their XBRL tags differ from every other company's (`InterestEarned` not `RevenueFromOperations`, etc.). Investigated rather than assumed NBFCs had the same problem — they don't, same tags as regular companies, already worked. Fixed banks specifically with their own tag set; ROCE/D-E deliberately left NULL for banks (not meaningful concepts for a bank's balance sheet), ROE/cash made real via bank-specific equity/cash tags.
10. **13F VALUE field 1000x too large** — built on the well-documented general SEC convention that Form 13F's VALUE is reported in thousands, and multiplied accordingly. Caught before it shipped: implied per-share price for NVIDIA came out to ~$139,566, absurd for any real stock. This bulk/normalized data set turns out to already report VALUE in whole dollars, unlike the convention for older raw filings — removed the `*1000`, re-checked against NVDA/AAPL, implied prices came out sane (~$140, ~$173).
11. **13F progress looked hung** — a full run maps ~3,000 CUSIPs via ~300 rate-limited OpenFIGI batches (~12 min) but only wrote rows to the DB *after* every batch had been mapped, so `rows_written` sat at 0 the entire time — indistinguishable from a real hang without checking CPU/network directly (confirmed: low CPU, steady network, genuinely just working). Fixed: map-and-write interleaved per batch, so progress is visible throughout like every other source.
12. **macro_context schema change didn't apply live** — `CREATE TABLE IF NOT EXISTS` doesn't alter an existing table, and this table had existed (empty) since the original design. Redesigning it from `quarter_label/note` to structured columns silently kept the old shape on the live DB until a write hit it (`no column named period_end_date`). Fixed with a one-time defensive migration in `init_db()` — safe to drop-and-recreate since the table had genuinely never held data.
13. **India Layer 2 silently dead** — `_compute_sector_benchmark`'s peer query hardcoded `qd.source = 'sec_edgar'`, so it only ever matched US peers — India (source `'bse'`) got zero peer rows and silently blank Layer 2/4, ever since BSE sector data landed. Found while building price-based momentum, not the original goal. Fixed by filtering on `market` instead of `source` — works for both markets, and is more correct anyway.
14. **sync_universe wiping real sector data** — `bse_source.py`, `fivepaisa_source.py`, and `sec_edgar_source.py` all `INSERT OR REPLACE`d into `stocks` with `sector` hardcoded to `'Unclassified'`. Since `fivepaisa_source.py` and `bse_source.py` write the same `NSE:{ticker}` symbol space, re-running either one's universe sync silently erased whatever real sector `_sector_for()` had already written for every stock — confirmed happening live (ABB, TATAMOTORS and others reverted to Unclassified after a 5paisa universe sync ran). Fixed all three with `INSERT ... ON CONFLICT(symbol) DO UPDATE` that excludes `sector` from the update clause, so an existing real value survives a re-sync.
15. **Operating Profit / OPM % wrong for every non-bank India company** — found by direct field-by-field comparison against Screener.in (Infosys): our figure was ~12% low, every quarter. Root cause: `operating_profit_cr` was computed as Revenue − BSE's `Expenses` XBRL tag, but that tag bundles Finance Costs and Depreciation in with opex — both belong *below* the operating-profit line. Confirmed precisely: the gap matched FinanceCosts + Depreciation to the rupee. Fixed by adding both back; re-verified against Screener afterward — exact match on all 6 quarters checked. Also affects ROCE (which uses operating profit), now corrected too.
16. **quarterly_data schema change on a table with real data** — same class of bug as #12, but this time the table (unlike `macro_context`) already held real, valuable data, so a drop-and-recreate wasn't an option. Added `pbt_cr`/`tax_pct`/`book_value_per_share` via `ALTER TABLE ADD COLUMN`, guarded to only run if the column doesn't already exist — tested directly against a simulated pre-migration DB with real rows to confirm no data loss before deploying.
17. **Ingestion parallelized** — not a bug fix, a real architecture change. The original single-worker queue (item 3 above) fixed a deadlock by serializing everything, but the deadlock's actual cause (a second connection opened mid-transaction) was fixed independently — meaning the serialization had been pure overhead ever since. With every source hitting a different external API (different rate-limit bucket each), a full sequential run of 5 queued sources was taking ~8.5 hours; parallel, bounded by the slowest single source, ~4 hours. Verified safe with real concurrent sources (BSE + SEC EDGAR + World Bank writing at once) in an isolated test before deploying.

## India — real now, via BSE-direct

`app/ingestion/bse_source.py`. Two dead ends first (Tijori — no API; NSE-direct — ~94% broken XBRL links, both verified directly), then BSE's own archive tested at 95% (19/20 large-caps) real, parseable filings — a materially different result from NSE despite both being "the same kind of exchange." No official public API; this reverse-engineers BSE's own frontend calls (`api.bseindia.com/BseIndiaAPI/api/...`), same integrity tier as any screen-scrape — no SLA, could break without notice if BSE changes their site.

Sector is now real too — `_sector_for()` pulls `IndustryNew` (mid-granularity: "Capital Goods", "Information Technology", "Oil, Gas & Consumable Fuels") from a separate per-scrip endpoint (`ComHeadernew_par`), since BSE's scrip-master list itself always returns `INDUSTRY: null` (confirmed empirically). This unblocks Layer 2 (sector-relative) and Layer 4 (sector momentum) for India — `_compute_sector_benchmark` in `analytics.py` works market-agnostically already, it just needed real sector values to bucket on.

**Validated field-by-field against Screener.in** (Infosys, consolidated, 6 recent quarters) — a real accuracy check, not just a plausibility glance. Revenue, Net Profit, EPS, PBT: exact match every quarter. Operating Profit/OPM: was ~12% low, root-caused and fixed (bug #15 above). Other Income: exact on 5/6 quarters, one quarter's gap traced to BSE's own raw filing (not our bug — no revision, no sign issue, we're faithfully reporting what's tagged). Now also extracting Other Income, PBT, Tax %, and Book Value per Share (bug #16) — Book Value came out ₹230 vs. Screener's ₹225, close enough to be standalone/consolidated noise. Borrowings/D-E investigated too: Infosys's own regulatory disclosure tag reports **zero** formal borrowings — Screener's ₹9,176cr figure is almost certainly lease liabilities folded into their own "Borrowings" presentation, and BSE's XBRL doesn't tag lease liabilities separately from other non-debt financial liabilities, so we can't cleanly replicate that number without risking misclassifying non-debt items as debt. Left as 0 — honest per the primary source, not a bug to chase.

Known gap, not yet built: **Dividend Yield** — confirmed no dividend tag exists anywhere in BSE's quarterly/annual XBRL filings (checked directly). Would need a separate source (BSE's corporate-actions feed, untested) — different data shape from everything else here, deliberately not rushed in.

Banks and NBFCs both now covered too. Investigated directly rather than assumed: NBFCs (e.g. Bajaj Finance) turned out to use the *same* tags as regular companies — revenue, profit, EPS, equity, cash, assets, all standard — so they were already working, no code change needed there. Only full commercial banks (HDFC Bank etc.) are genuinely different: revenue is `InterestEarned` not `RevenueFromOperations`, operating profit is a direct tag (`OperatingProfitBeforeProvisionAndContingencies`) instead of Revenue−Expenses, and equity is `Capital + ReservesAndSurplus` with cash as the RBI-balance tag, not the standard ones. ROCE and D/E are left NULL for banks specifically — "Capital Employed" and "debt" aren't meaningful concepts for a bank's balance sheet (deposits are the core business, not leverage); ROE and cash both work correctly. One more real fix along the way: NBFCs report a single combined `Borrowings` tag instead of the split current/noncurrent pair regular companies use — added as a fallback.

P/E is real for India too now — see the `5paisa` row above.

Vendor pricing (Capitaline, Accord Fintech, FinEdge, IndianAPI.in) and Screener.in's ToS/scraping legitimacy were researched in parallel — kept as fallback context, not needed now that BSE-direct works. Screener.in remains a good validation source (cross-check our numbers against theirs), not a primary pipeline, per its ToS.

**Future option, once there's budget: BSE's own official data-vendor program.** Checked their published pricing sheet directly (`BSE Information Products Domestic Tariff Sheet`, Feb 2025 — a real, concrete price list, unlike Capitaline/Accord Fintech which never publish one). NSE's equivalent sheet has no fundamentals product at all — pure trading data (quotes, order book, EOD prices). BSE's "Corporate Data" tier is the relevant one:

| Product | EOD price | Relevance |
|---|---|---|
| Financial Results | ₹3,00,000/yr | Exactly what `bse_source.py` reverse-engineers today |
| Shareholding Pattern | ₹3,00,000/yr | **We don't have this at all** — promoter %/FII %/DII % are NULL in our schema currently |
| Financial Results Calendar | ₹3,00,000/yr | Tells you when results are due — useful for scheduling ingestion |
| Historical OHLC (per stock) | ₹75,000/yr | Could replace/supplement 5paisa price data |
| Company/Scrip Master | ₹35,000-1,00,000/yr | Official version of what we scrape free today |

All ex-tax, INR, EOD delivery (continuous/real-time tiers cost more). Roughly **₹8-10 lakh/year (~$9,500-12,000/year)** for Results + Shareholding + OHLC together — a real, licensed, stable replacement for the current undocumented/no-SLA reverse-engineered pipeline, and it would newly unlock shareholding pattern data we've never had. Not urgent — BSE-direct works today — but worth revisiting once there's a budget for it, since the price point is far more approachable than the enterprise-sales-only vendors (Capitaline etc.).

**Deeper-history feasibility test (annual reports, PDF vs. XBRL) — investigated, not built.** Both BSE's and BSE/NSE's XBRL feeds only go back ~1.5-2yrs; the question was whether their full annual-report archives (PDF) could extend real history further, without touching live ingestion. Tested end-to-end, isolated, on two real documents:

- **BSE — Wipro** (`AnnualReport_New/w?scripcode=` endpoint), 561-page PDF, downloaded directly. Full-document text search for the Cash Flow Statement: **75s**, **20 ambiguous matches** (mentions vs. the actual statement). `pdfplumber.extract_tables()` on the real statement page separated numeric columns correctly but returned `None` for every row-label cell — numbers with no attached meaning. A rotated vertical sidebar label came back reversed/interleaved-garbled (`62-5202 | TROPER | LAUNNA...` instead of "2025-26 ANNUAL INTEGRATED REPORT WIPRO").
- **NSE — HDFC Bank** (`corporate-filings-annual-reports`, direct static PDF under `nsearchives.nseindia.com`, no scripcode lookup needed), 678-page PDF, 12MB, downloaded in <1s. Full-document search for the Cash Flow Statement: **65s**, **31 ambiguous matches**. `extract_tables()` failed harder than BSE's — returned only the header row, no data at all. But plain `extract_text()` on the Balance Sheet / P&L / Cash Flow pages came back clean: label, schedule ref, and both years' values in reading order on one line, no garbling anywhere sampled (cover pages through page 10, and the financial-statement pages themselves) — a regex line-parser (not table extraction) looks genuinely viable here, unlike Wipro.

Verdict: table-based PDF extraction is not reliable across either exchange's annual reports (`None` labels on BSE, empty tables on NSE) — not worth building as the general approach. Text-line regex parsing looked promising specifically on HDFC Bank's PDF but wasn't validated on a second document, and either way a ~65-75s full-document search per filing (before any extraction) makes bulk ingestion (thousands of filings) impractically slow without also building page-locating heuristics first. **Also found in passing:** NSE has a separate, working **"Annual Report-XBRL"** archive (`corporate-filings-annual-reports-xbrl`) — genuine structured XBRL (not PDF), same MCA/Ind-AS taxonomy as BSE's, publicly downloadable with no auth (verified: TCS FY26 net profit tag matched the filing's own footnote exactly, ₹49,096cr). Confirmed working for TCS and Reliance; confirmed **"No Records" for both HDFC Bank and ICICI Bank** — banks appear excluded from this filing category (likely filed under Banking Regulation Act disclosures instead of the Companies Act/MCA taxonomy this endpoint serves). Same ~2yr depth cap as BSE's XBRL, so it doesn't extend history — but for non-bank companies within that window it's strictly better data quality than either exchange's PDF path, and worth using as a second structured India source later if bank coverage stops mattering enough, or a bank-specific taxonomy source is found.

Net: no current path to real fundamentals history beyond BSE's existing ~2yr XBRL window without paying for a vendor (see pricing table above). Not pursuing PDF parsing further right now.
